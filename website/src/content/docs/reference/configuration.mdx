## Files and precedence {#files}

`Vorpal.toml` sits in the project root. Six keys are also *settings* you can set for yourself, on this machine, in `~/.vorpal/settings.json` with `vorpal config --user set`: `language`, `name`, `namespace`, `registry`, `system`, `worker`.

Each setting is read from, in order: a flag on the command line, `Vorpal.toml`, `~/.vorpal/settings.json`, then the built-in default.

### `language` {#key-language}

<Props file="`Vorpal.toml`, `settings.json`" type="string" default="`rust`" allowed="`go`, `python`, `rust`, `typescript`" flag="none (setting: `vorpal config set language`)" />

The SDK your config program is written in. Any other value stops the build with [`Unsupported language`](/troubleshooting/errors/#err-unsupported-language).

```toml title="Vorpal.toml"
language = "python"
```

### `name` {#key-name}

<Props file="`Vorpal.toml`, `settings.json`" type="string" default="`vorpal`" allowed="any" flag="none (setting)" />

The config program's name. It sets default file names, such as `src/<name>.py` for Python.

```toml title="Vorpal.toml"
name = "vorpal"
```

### `namespace` {#key-namespace}

<Props file="`Vorpal.toml`, `settings.json`" type="string" default="`library`" flag="[`--namespace`](/reference/cli/build/#flag-namespace)" />

The namespace artifacts are stored in.

```toml title="Vorpal.toml"
namespace = "my-team"
```

### `registry` {#key-registry}

<Props file="`Vorpal.toml`, `settings.json`" type="string" default="`unix:///var/lib/vorpal/vorpal.sock`" allowed="a `unix://`, `http://` or `https://` address" flag="[`--registry`](/reference/cli/build/#flag-registry)" env="`VORPAL_SOCKET_PATH` changes the default socket" />

Where the CLI and the agent daemon find the registry.

```toml title="Vorpal.toml"
registry = "https://build.example.com:23151"
```

### `system` {#key-system}

<Props file="`Vorpal.toml`, `settings.json`" type="string" default="this machine's system" allowed="`aarch64-darwin`, `aarch64-linux`, `x86_64-darwin`, `x86_64-linux`" flag="[`--system`](/reference/cli/build/#flag-system)" />

The system to build for.

```toml title="Vorpal.toml"
system = "x86_64-linux"
```

### `worker` {#key-worker}

<Props file="`Vorpal.toml`, `settings.json`" type="string" default="`unix:///var/lib/vorpal/vorpal.sock`" allowed="a `unix://`, `http://` or `https://` address" flag="[`--worker`](/reference/cli/build/#flag-worker)" env="`VORPAL_SOCKET_PATH` changes the default socket" />

Where builds run.

```toml title="Vorpal.toml"
worker = "https://build.example.com:23151"
```

### `environments` {#key-environments}

<Props file="`Vorpal.toml`" type="list of strings" default="not set" allowed="`KEY=VALUE` strings" flag="none" />

Environment variables for building the config program.

```toml title="Vorpal.toml"
environments = ["EXAMPLE=value"]
```

### `source.includes` {#key-source-includes}

<Props file="`Vorpal.toml` `[source]`" type="list of strings" default="depends on `language`, see below" allowed="paths relative to `--context`" flag="none" />

The files Vorpal hashes into the config program. Keep it small: any change to these files rebuilds the config program. A list given here replaces the default list.

- Go: `<name>.go`, `go.mod`, `go.sum`
- Python: `pyproject.toml`, `uv.lock`, `src`, `README.md`
- Rust: `src/<name>.rs`, `Cargo.toml`, `Cargo.lock`
- TypeScript: `bun.lock`, `bun.lockb`, `package.json`, `tsconfig.json` and the entrypoint

```toml title="Vorpal.toml"
[source]
includes = ["pyproject.toml", "uv.lock", "src"]
```

### `source.script` {#key-source-script}

<Props file="`Vorpal.toml` `[source]`" type="string" default="not set" flag="none" />

A shell script that runs on the source before a Go config program is built. Only the Go SDK uses it.

```toml title="Vorpal.toml"
[source]
script = "./generate.sh"
```

### `source.go.directory` {#key-source-go-directory}

<Props file="`Vorpal.toml` `[source.go]`" type="string" default="not set" allowed="a folder inside `source.includes`" flag="none" />

The Go package folder that holds the config program's `main.go`.

```toml title="Vorpal.toml"
[source.go]
directory = "cmd/vorpal"
```

### `source.python.directory` {#key-source-python-directory}

<Props file="`Vorpal.toml` `[source.python]`" type="string" default="not set" allowed="a folder relative to `--context`" flag="none" />

The working folder for the Python config program.

```toml title="Vorpal.toml"
[source.python]
directory = "."
```

### `source.python.entrypoint` {#key-source-python-entrypoint}

<Props file="`Vorpal.toml` `[source.python]`" type="string" default="`src/<name>.py`, so `src/vorpal.py` with the default `name`" allowed="a path inside `source.includes`" flag="none" />

The Python file the config program starts from.

```toml title="Vorpal.toml"
[source.python]
entrypoint = "src/vorpal.py"
```

### `source.rust.bin` {#key-source-rust-bin}

<Props file="`Vorpal.toml` `[source.rust]`" type="string" default="the value of `name`" flag="none" />

The Cargo binary to build as the config program.

```toml title="Vorpal.toml"
[source.rust]
bin = "vorpal-config"
```

### `source.rust.packages` {#key-source-rust-packages}

<Props file="`Vorpal.toml` `[source.rust]`" type="list of strings" default="not set" flag="none" />

The Cargo packages of a workspace to build.

```toml title="Vorpal.toml"
[source.rust]
packages = ["vorpal-config", "vorpal-sdk"]
```

### `source.typescript.directory` {#key-source-typescript-directory}

<Props file="`Vorpal.toml` `[source.typescript]`" type="string" default="not set" allowed="a folder relative to `--context`" flag="none" />

The working folder for the TypeScript config program.

```toml title="Vorpal.toml"
[source.typescript]
directory = "."
```

### `source.typescript.entrypoint` {#key-source-typescript-entrypoint}

<Props file="`Vorpal.toml` `[source.typescript]`" type="string" default="`src/<name>.ts`, so `src/vorpal.ts` with the default `name`" allowed="a path inside `source.includes`" flag="none" />

The TypeScript file the config program starts from.

```toml title="Vorpal.toml"
[source.typescript]
entrypoint = "src/vorpal.ts"
```

## Examples {#examples}

### Rust

```toml
language = "rust"
name = "vorpal-config"

[source]
includes = [
    "config",
    "sdk/rust",
]

[source.rust]
packages = [
    "vorpal-config",
    "vorpal-sdk",
]
```

### Go

```toml
language = "go"

[source]
includes = ["sdk/go"]

[source.go]
directory = "sdk/go/cmd/vorpal"
```

### Python

```toml
language = "python"

[source]
includes = [
    "sdk/python/src",
    "sdk/python/pyproject.toml",
    "sdk/python/uv.lock",
    "sdk/python/README.md"
]

[source.python]
directory = "sdk/python"
entrypoint = "src/vorpal_sdk/vorpal.py"
```

### TypeScript

```toml
language = "typescript"

[source]
includes = [
    "sdk/typescript/src",
    "sdk/typescript/bun.lock",
    "sdk/typescript/package.json",
    "sdk/typescript/tsconfig.json"
]

[source.typescript]
directory = "sdk/typescript"
entrypoint = "src/vorpal.ts"
```

## Your settings file {#settings-json}

`~/.vorpal/settings.json` holds your settings on this machine, as JSON. They apply to every project, unless its `Vorpal.toml` sets the same key. `VORPAL_USER_CONFIG_DIR` changes the folder.

```json title="~/.vorpal/settings.json"
{
  "registry": "https://registry.example.com:23151",
  "namespace": "my-team",
  "worker": "https://worker.example.com:23151"
}
```

Every key is optional; a key that is not set keeps the built-in default.

```bash prompt
# Set a value in your settings file
vorpal config --user set registry "https://registry.example.com:23151"

# Get a value (shows resolved source)
vorpal config get registry

# Show all values with sources
vorpal config show
```

## Lockfile {#lockfile-vorpallock}

`Vorpal.lock` pins the digest of each remote source, per platform. `vorpal prepare` (or a build with `--unlock`) writes it; commit it with your project.

```toml title="Vorpal.lock"
lockfile = 1

[[sources]]
name = "source-name"
digest = "sha256-hex-digest"
platform = "aarch64-darwin"
path = "https://example.com/archive.tar.gz"
includes = []
excludes = []
```

- A build runs in locked mode: it stops on a remote source with no pin ([`is unpinned`](/troubleshooting/errors/#err-source-unpinned)) or one that no longer matches its pin ([`changed`](/troubleshooting/errors/#err-source-changed)).
- Each entry is for one platform.

```bash prompt
# Pin or update the sources
vorpal prepare my-app
# Build in locked mode
vorpal build my-app
```

## Storage layout {#storage-layout}

Vorpal stores all data under `/var/lib/vorpal/`:

| Path | Purpose |
|------|---------|
| `vorpal.sock` | Unix domain socket for service communication |
| `vorpal.lock` | Advisory lock file preventing concurrent server instances (name derived from the socket path stem) |
| `key/` | TLS certificates, keypairs, and credentials |
| `store/artifact/alias/` | Named references mapping aliases to artifact digests |
| `store/artifact/archive/` | Compressed (zstd) artifact archives |
| `store/artifact/config/` | Compiled configuration outputs |
| `store/artifact/output/` | Unpacked artifact outputs |
| `sandbox/` | Isolated build workspaces |

## Supported systems {#supported-systems}

[`system`](#key-system) and `--system` take these values:

| Value | Platform |
|-------|----------|
| `aarch64-darwin` | macOS Apple Silicon |
| `x86_64-darwin` | macOS Intel |
| `aarch64-linux` | Linux ARM64 |
| `x86_64-linux` | Linux x86_64 |
