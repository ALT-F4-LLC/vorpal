## Synopsis {#synopsis}

<CliSynopsis command="prepare" />

`prepare` downloads and pins every remote source of the artifact and its dependencies in `Vorpal.lock`, and builds nothing but the config program and its toolchain (for example `protoc` for a Go config program). The config program always runs on the host, so any host can prepare any `--system`.

<CliEntries command="prepare" kind="options" />

The `registry`, `worker`, `namespace` and `system` settings replace these defaults: `Vorpal.toml` first, then `~/.vorpal/settings.json`. A flag on the command line always wins.

**Global options:** [`--level`](/reference/cli/#flag-level) sets the log level for every command.

## Examples {#examples}

```bash prompt
# Pin or update the sources of my-app
vorpal prepare my-app
# In CI: stop on any unpinned or changed source, as build does
vorpal prepare my-app --unlock=false
# Pin the sources for another system, from any host
vorpal prepare my-app --system x86_64-darwin
```

## Output {#output}

One line for every remote (HTTP or HTTPS) source of the artifact and its dependencies, sorted, then the artifact's digest, as `vorpal build` prints it:

```text output
verify: <name> (<platform>) -> <digest>
update: <name> (<platform>) -> <digest>
mint: <name> (<platform>) -> <digest>
<digest>
```

- `mint:` the source had no pin; this is the first pin.
- `update:` the pin changed.
- `verify:` the pin is unchanged.

## Errors and exit codes {#errors}

- [`selected 'artifact' not found: <NAME>`](/troubleshooting/errors/#err-selected-artifact-not-found)
- With `--unlock=false`: [`source '<name>' changed - use '--unlock' to update`](/troubleshooting/errors/#err-source-changed) and [`source '<name>' is unpinned - use '--unlock' to pin`](/troubleshooting/errors/#err-source-unpinned)

Exit code 0 on success, 1 on an error, 2 for a usage error such as `--unlock false` (write `--unlock=false`).
